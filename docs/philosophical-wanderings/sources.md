What you gain: the moving-target risk (tension #3) disappears, and the purpose becomes timeless — Wilkinson's grammar of graphics is from 1999 and still foundational, while "AI-native" will date itself.
In Meadows' terms: the thought experiment proves AI-native was sitting at the positioning level, not the paradigm level. The weave is the paradigm. And a purpose statement should be built from paradigm-level material — so making 0.5 into Principle 1 isn't just a valid alternative, it's arguably the more correct ordering that the first draft got backwards.

There's also a free lunch hiding here: a grammar with machine-readable contracts is automatically AI-composable. Constrained composition over vetted primitives is exactly what the generative-UI literature says agents need — so if you build the weave properly, AI-nativeness re-emerges as a consequence you can claim in positioning, without ever being a design goal you must chase. You can remove it from the purpose and lose essentially none of the capability.

The revised proposal
Purpose statement (v2):

Cuboid is a generative grammar of interfaces woven from three foundations — the web's own semantics, the structure of data, and the constants of human cognition. A small set of primitives and composition rules from which anyone can compose any interface, from data-dense enterprise tools to simple pages, with accessibility and cognitive soundness guaranteed by construction.

Principle 1 — One weave, expanded, with the arbitration rule that gives it teeth:

Every primitive must have an account in all three theories: as platform semantics, as an operation on typed data, and as an object-or-instrument under cognitive constraints. If a proposed part lacks one of the three accounts, it is not yet foundational — it's a convenience, and it belongs in the derived layer or nowhere.

The three accounts, each resting on its mature theory:

Web — the platform is already a semantic system; enrich it, never parallel it. HTML elements carry meaning, ARIA extends that meaning to widgets HTML lacks, and the accessibility tree is a machine-readable projection the platform already ships — Cuboid's semantic layer should be that projection, not a private vocabulary beside it. React Aria's contribution is the proof that a component decomposes into state / behavior / rendering, with the first two separable and adoptable — so the grammar can own composition and rendering while inheriting hardened behavior. The test for any primitive: does it project cleanly onto the accessibility tree? If a composition can't be expressed in platform semantics, it's outside the grammar.

Data — representation is an algebra, not a taxonomy. Wilkinson's insight, operationalized by Vega-Lite: charts aren't a list of types (bar, pie, line) but expressions in a pipeline — typed fields (quantitative, ordinal, nominal, temporal) → transforms → scales → encoding channels → marks, plus a composition algebra. The extension nobody has made: generalize the channels beyond position and color to structural channels — column, row, grouping, hierarchy depth, sort order, emphasis. Then a table, a tree view, a kanban board, and a list are all the same thing: encodings of typed collections with different mark systems. Cuboid's existing data views are the natural first proof, and where the "data-intensive enterprise" half of your ambition gets its credibility.

Cognition — constants as constraints, and an interaction model underneath. Two strata. First, the perceptual/motor invariants from experimental psychology, encoded where they can't be ignored: Fitts's law as token floors on target size and spacing; Hick–Hyman as choice-count thresholds that trigger progressive disclosure or search; working-memory limits as chunking rules in forms and navigation; Gestalt proximity as the requirement that the spacing scale keep "related" and "unrelated" perceptibly distinct ratios. Advice in documentation decays; constraints in the grammar generate correctness — this is where Principle 1 and "valid by construction" fuse. Second, the model: Beaudouin-Lafon's instrumental interaction says interfaces are domain objects plus instruments that mediate action on them — so Cuboid's primitives are objects and instruments, not widgets. A date picker is an instrument acting on a temporal value; a table is a collection object with sort and selection instruments attached; and his evaluation criteria for instruments (degree of indirection, integration, compatibility) become review criteria for every new primitive.

The seams are where the weave earns the word "true." Each pairwise junction is itself principled: data×web — every encoding must emit platform semantics (a table encoding produces real grid/table roles, so structure reaches assistive tech for free); web×cognition — platform behaviors run under motor constraints (focus order, target sizes); data×cognition — the choice of encoding channel follows perceptual effectiveness, where Cleveland & McGill's graphical-perception experiments (the ranking Vega-Lite's defaults derive from) tell you position beats length beats angle beats color for quantitative accuracy. Instruments attach to encodings — sort attaches to a column channel, filter to a field — which is the moment all three pillars touch.

My verdict, since you asked for the proposal and not just the analysis: this version is the stronger ontology. The weave is what's actually novel and defensible; AI-composability comes along free and can live in positioning (§0.3) as a demonstrated consequence rather than in the purpose. The one thing I'd preserve from the old draft is contracts-as-data as an engineering principle — it's what keeps the free lunch free.
